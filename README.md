# TerminalPlotter

TerminalPlotter — консольное приложение на C++ для построения графиков простых математических функций в терминале.

Проект предназначен для учебной работы по тестированию программного обеспечения. Основной способ проверки приложения — тестирование методом «чёрного ящика»: тестировщик ориентируется на требования из этого файла и сравнивает фактическое поведение программы с ожидаемым.

---

## 1. Назначение программы

Программа должна:

- принимать от пользователя одну из поддерживаемых математических функций;
- принимать границы диапазона по оси X;
- вычислять значения функции на выбранном диапазоне;
- отображать график в терминале;
- корректно обрабатывать функции с ограниченной областью определения;
- отображать координатные оси, если они попадают в видимую область;
- не завершаться аварийно при некорректном пользовательском вводе;
- позволять многократно строить новые графики без перезапуска программы;
- завершаться по команде `exit`.

---

## 2. Сборка и запуск

Требуется:

- CMake 3.16 или новее;
- компилятор с поддержкой C++17.

Сборка из корня проекта:

```bash
cmake -S . -B build
cmake --build build
```

Запуск:

```bash
./build/terminal_plotter
```

Форматирование исходного кода:

```bash
cmake --build build --target clang-format
```

## 3. Стартовый экран

После запуска программа должна вывести информацию примерно следующего вида:

```text
==================================
         Terminal Plotter
==================================

Available functions:
  x
  x^2
  sin(x)
  cos(x)
  sqrt(x)
  log(x)
  abs(x)
  1/x

Type 'exit' to quit.

Enter function:
```

После построения одного графика программа не должна завершаться. Пользователь должен снова получить приглашение:

```text
Enter function:
```

и иметь возможность построить следующий график.

---

## 4. Поддерживаемые функции

Программа версии 1.0 должна распознавать только следующие записи:

| Ввод пользователя | Математическая функция | Область определения |
|---|---|---|
| `x` | `y = x` | все действительные X |
| `x^2` | `y = x²` | все действительные X |
| `sin(x)` | `y = sin(x)` | все действительные X |
| `cos(x)` | `y = cos(x)` | все действительные X |
| `sqrt(x)` | `y = √x` | `x >= 0` |
| `log(x)` | `y = ln(x)` | `x > 0` |
| `abs(x)` | `y = |x|` | все действительные X |
| `1/x` | `y = 1/x` | `x != 0` |

`log(x)` означает натуральный логарифм.

Произвольные выражения в версии 1.0 не поддерживаются. Например, следующие строки должны считаться неподдерживаемыми:

```text
2*x + 3
sin(x) + cos(x)
x^3
sqrt(x + 2)
SIN(x)
```

Распознавание названий функций регистрозависимое.

---

## 5. Ввод функции

После строки:

```text
Enter function:
```

пользователь вводит одну из поддерживаемых функций.

Пример корректного ввода:

```text
Enter function: sin(x)
```

Если введена неподдерживаемая функция, программа должна вывести сообщение об ошибке и снова запросить функцию.

Пример:

```text
Enter function: test(x)
Error: unsupported function.

Enter function:
```

Программа не должна аварийно завершаться из-за неизвестного имени функции.

---

## 6. Ввод диапазона X

После успешного выбора функции программа запрашивает:

```text
X min:
X max:
```

Допускаются целые и вещественные конечные числа, в том числе отрицательные и числа в экспоненциальной записи.

Корректные примеры:

```text
10
-10
3.14
-0.25
1e3
```

Строка должна целиком представлять число.

Поэтому такие значения должны быть отклонены:

```text
abc
10abc
3.14test
--
```

При некорректном вводе программа должна вывести сообщение об ошибке и повторно запросить соответствующее значение.

Пример:

```text
X min: abc
Error: X min must be a valid number.
X min:
```

---

## 7. Требования к диапазону

Должно выполняться условие:

```text
X min < X max
```

Если `X min` больше или равен `X max`, диапазон считается некорректным.

Пример:

```text
X min: 5
X max: 5
Error: X max must be greater than X min.
X max:
```

То же правило действует для:

```text
X min: 10
X max: -10
```

Программа не должна пытаться строить график для диапазона нулевой или отрицательной длины.

---

## 8. Команда выхода

Команда:

```text
exit
```

должна завершать программу.

Она должна работать как минимум при вводе функции, `X min` и `X max`.

Пример:

```text
Enter function: exit

Goodbye!
```

или:

```text
Enter function: sin(x)
X min: exit

Goodbye!
```

После команды `exit` программа должна корректно завершиться без аварийного остановa.

---

## 9. Расчёт точек графика

По умолчанию ширина области графика составляет:

```text
80 колонок
```

Высота:

```text
25 строк
```

Для построения должно рассчитываться 80 точек функции.

Первая рассчитанная точка должна соответствовать:

```text
x = X min
```

Последняя рассчитанная точка должна соответствовать:

```text
x = X max
```

То есть обе границы заданного пользователем диапазона должны входить в расчёт.

Для `width = 80` шаг по X должен определяться как:

```text
step = (X max - X min) / (width - 1)
```

Значение каждой точки:

```text
x_i = X min + i * step
```

где `i` принимает значения от `0` до `width - 1`.

## 10. Область определения функций

Если отдельная точка находится вне области определения функции, приложение не должно падать и не должно использовать некорректное значение при масштабировании.

### `sqrt(x)`

При:

```text
x < 0
```

точка не отображается.

При:

```text
x = 0
```

значение существует:

```text
sqrt(0) = 0
```

Пример:

```text
Function: sqrt(x)
X min: -10
X max: 10
```

График должен отображаться только для `x >= 0`.

### `log(x)`

При:

```text
x <= 0
```

точка не отображается.

Пример:

```text
Function: log(x)
X min: 0
X max: 20
```

Программа не должна падать. Точка `x = 0` пропускается, а остальные допустимые точки отображаются.

Если весь выбранный диапазон лежит вне области определения, например:

```text
Function: log(x)
X min: -20
X max: 0
```

программа должна сообщить:

```text
No valid points in selected range.
```

и продолжить работу.

### `1/x`

При:

```text
x = 0
```

точка не существует и не отображается.

Левая и правая ветви гиперболы не должны соединяться линией через `x = 0`.

---

## 11. Требования к отображению графика

График строится в текстовом терминале.

Основной символ графика:

```text
*
```

Соседние рассчитанные точки должны визуально соединяться, чтобы график выглядел непрерывным там, где математическая функция непрерывна.

Для соединения точек допускается растеризация линии между соседними экранными координатами.

При этом нельзя соединять точки через участок, в котором функция не определена.

Особенно это относится к:

```text
1/x
log(x)
sqrt(x)
```

---

## 12. Масштабирование по оси Y

Границы отображения по Y определяются автоматически по минимальному и максимальному корректным значениям функции в текущем диапазоне.

Некорректные значения:

```text
NaN
+inf
-inf
```

не должны участвовать в расчёте масштаба.

Максимальное корректное значение функции отображается около верхней границы области графика.

Минимальное корректное значение отображается около нижней границы.

Если все корректные значения функции одинаковы, график должен отображаться без деления на ноль при масштабировании.

---

## 13. Координатные оси

### Ось Y

Вертикальная ось Y соответствует:

```text
x = 0
```

Она должна отображаться только если ноль входит в диапазон X:

```text
X min <= 0 <= X max
```

Положение оси должно рассчитываться по фактическому положению нуля внутри диапазона.

Например, для:

```text
X min = -10
X max = 10
```

ось Y находится примерно по центру.

Но для:

```text
X min = -5
X max = 15
```

ось Y должна находиться примерно на четверти ширины графика, а не по центру.

Символ оси Y:

```text
|
```

### Ось X

Горизонтальная ось X соответствует:

```text
y = 0
```

Она отображается только в том случае, если `0` входит в отображаемый диапазон Y.

Символ оси X:

```text
-
```

Если оси X и Y пересекаются, точка пересечения может обозначаться:

```text
+
```

График функции рисуется поверх координатных осей.

---

## 14. Подписи границ

Программа должна отображать рассчитанные границы графика.

По вертикали должны выводиться значения:

```text
Y max
Y min
```

По горизонтали:

```text
X min
X max
```

Числовые подписи отображаются с точностью до двух знаков после десятичной точки.

Например, при вводе:

```text
X min: -10
X max: 10
```

нижняя строка должна содержать границы вида:

```text
-10.00                                                               10.00
```

Правая подпись должна соответствовать именно введённому `X max`, поскольку правая граница входит в набор рассчитанных точек.

---

## 15. Ожидаемые свойства отдельных функций

| Функция | Проверяемое ожидаемое поведение |
|---|---|
| `x` | возрастающая прямая, проходит через `(0, 0)`, если ноль входит в диапазон |
| `x^2` | парабола, неотрицательные значения, минимум около `(0, 0)` |
| `sin(x)` | синусоида, при `x = 0` значение равно `0` |
| `cos(x)` | косинусоида, при `x = 0` значение равно `1` |
| `sqrt(x)` | отображается только при `x >= 0`, начинается с `(0, 0)`, если ноль включён |
| `log(x)` | отображается только при `x > 0`, не определён при `x = 0` |
| `abs(x)` | V-образный график, минимум в `(0, 0)` |
| `1/x` | две отдельные ветви, значение не определено при `x = 0` |

---

## 16. Обработка ошибок

Ни один из следующих пользовательских сценариев не должен приводить к аварийному завершению программы:

| Сценарий | Ожидаемое поведение |
|---|---|
| Неизвестная функция | Сообщение об ошибке, повторный ввод функции |
| `X min = abc` | Сообщение об ошибке, повторный ввод |
| `X max = 10abc` | Сообщение об ошибке, повторный ввод |
| `X min = X max` | Ошибка диапазона |
| `X min > X max` | Ошибка диапазона |
| `log(x)` при диапазоне с `x <= 0` | Недопустимые точки пропускаются |
| `sqrt(x)` при диапазоне с `x < 0` | Недопустимые точки пропускаются |
| `1/x` при диапазоне через `0` | Разрыв графика, без деления на ноль и без соединения ветвей |
| Диапазон полностью вне области определения | Сообщение `No valid points in selected range.` |
| `exit` | Корректное завершение |

## 17. Критерии приёмки

Версия приложения считается соответствующей техническому заданию, если выполняются следующие требования:

| ID | Требование |
|---|---|
| FR-01 | Все 8 заявленных функций распознаются корректно |
| FR-02 | Неизвестные функции отклоняются без завершения программы |
| FR-03 | `X min` и `X max` принимают только полностью корректные конечные числа |
| FR-04 | Выполняется строгое условие `X min < X max` |
| FR-05 | Обе границы X входят в расчёт точек |
| FR-06 | `sqrt(x)` корректно обрабатывает границу `x = 0` |
| FR-07 | `log(x)` не вычисляется при `x <= 0` |
| FR-08 | `1/x` не вычисляется при `x = 0` |
| FR-09 | Программа не соединяет график через разрывы области определения |
| FR-10 | Ось Y отображается в реальном положении `x = 0` |
| FR-11 | Ось X отображается в реальном положении `y = 0` |
| FR-12 | Подписи границ соответствуют фактическому диапазону |
| FR-13 | Некорректные значения `NaN` и `inf` не ломают Renderer |
| FR-14 | После построения графика можно построить следующий без перезапуска |
| FR-15 | Команда `exit` корректно завершает приложение |
| FR-16 | Некорректный пользовательский ввод не приводит к crash |

## 18. Что не входит в версию 1.0

В текущей версии не требуется поддерживать:

- произвольные формулы вроде `2*x + 3`;
- комбинации функций вроде `sin(x) + cos(x)`;
- пользовательские размеры графика;
- GUI;
- сохранение графика в файл;
- несколько графиков одновременно;
- пользовательский масштаб по Y;
- цветной вывод;
- производные, интегралы и другие математические операции.

Если программа отклоняет такие возможности, это не является дефектом версии 1.0.

## 19. Рекомендации тестировщику

Тестирование должно выполняться исходя из требований данного README, без анализа внутренней реализации программы.

Особое внимание рекомендуется уделить:

- граничным значениям;
- некорректному вводу;
- диапазонам, пересекающим границы области определения;
- асимметричным диапазонам X;
- точкам `x = 0`;
- визуальному соответствию выбранной функции;
- отсутствию аварийных завершений;
- соответствию подписей фактически введённым границам.

При обнаружении отклонения от данного технического задания рекомендуется оформить отдельный баг-репорт с шагами воспроизведения, ожидаемым результатом, фактическим результатом и оценкой критичности.
